# 처리 흐름

서버 시작 단계에서 미리 준비하는 것과, 메인 라우트 `POST /v1/tts`가 요청을 받아 응답을 보낼 때까지의 흐름을 설명합니다.

```
시작:  모델 로딩 → 보이스 준비 → 동시 처리 제한 설정

요청:  인증 → 입력 검사 → 보이스·언어 확인 → 대기 → 합성 → 인코딩 → 응답
```

## 1. 서버 시작 시 (한 번만 준비)

코드: [`app/main.py`](../app/main.py) `lifespan`, [`app/engine.py`](../app/engine.py) `TTSEngine.__init__`

| 단계 | 내용 |
|---|---|
| 모델 로딩 | `models/supertonic-3/onnx/`의 ONNX 모델 4개를 메모리에 올립니다. 몇 초 걸리므로 요청마다 하지 않고 시작할 때 한 번만 합니다. |
| 보이스 준비 | 내장 보이스 10개(F1–F5, M1–M5)를 미리 읽어 둡니다. `TTS_CUSTOM_VOICES_DIR`가 설정되어 있으면 커스텀 보이스도 함께 읽습니다. |
| 동시 처리 제한 | 동시에 진행할 합성 수를 `TTS_MAX_CONCURRENCY`(기본 1)로 제한합니다. 그 이상 들어온 요청은 순서대로 기다립니다. |

ONNX 모델은 다음 4개입니다.

| 파일 | 역할 |
|---|---|
| `duration_predictor.onnx` | 발화 길이 예측 |
| `text_encoder.onnx` | 텍스트를 임베딩으로 변환 |
| `vector_estimator.onnx` | 잡음을 음성 잠재값으로 반복 정제 (`steps`회) |
| `vocoder.onnx` | 잠재값을 실제 파형(44.1kHz)으로 변환 |

## 2. `POST /v1/tts` 요청 처리 흐름

코드: [`app/main.py`](../app/main.py) `tts()` → `synthesize()`

| # | 단계 | 내용 | 실패 시 |
|---|---|---|---|
| 1 | 인증 확인 | `TTS_API_KEY`가 설정된 경우에만 `Authorization: Bearer` 헤더를 확인합니다. | `401` |
| 2 | 입력 검사 | JSON 형식과 값 범위(텍스트 길이, speed 0.7–2.0, steps 1–50, 포맷)를 확인하고, 빠진 값은 기본값(F1, ko)으로 채웁니다. | `422` |
| 3 | 보이스·언어 확인 | 없는 보이스이거나 지원하지 않는 언어인지, 텍스트가 공백뿐인지 확인합니다. | `400` |
| 4 | 차례 대기 | 다른 합성이 진행 중이면 끝날 때까지 기다립니다. | - |
| 5 | 음성 합성 | 별도 스레드에서 실행되므로 합성 중에도 다른 요청은 막히지 않습니다. 아래 상세 참고. | `500` |
| 6 | 파일 변환 | 요청한 포맷(wav/mp3/flac/ogg)으로 인코딩합니다. | `500` |
| 7 | 응답 | 오디오 데이터와 함께 헤더에 오디오 길이와 처리 시간을 담아 보냅니다. | - |

1–2단계는 FastAPI가 라우트 함수를 실행하기 전에 자동으로 처리합니다.

### 5단계 음성 합성 상세 (Supertonic SDK 내부)

1. 텍스트를 정규화합니다. 이모지와 특수문자를 정리하고 언어 토큰을 붙입니다.
2. 긴 텍스트는 청크로 나눕니다. 한국어는 120자, 그 외 언어는 300자 단위입니다.
3. 청크마다 ONNX 모델 4개를 순서대로 실행합니다. 발화 길이 예측 → 텍스트 인코딩 → 음성 생성(`steps`회 반복) → 파형 변환 순입니다.
4. 청크 사이에 `silence`초만큼 무음을 넣어 이어 붙입니다.

### 응답 헤더

| 헤더 | 내용 |
|---|---|
| `Content-Type` | `audio/wav`, `audio/mpeg`, `audio/flac`, `audio/ogg` |
| `X-Audio-Duration` | 생성된 오디오 길이(초) |
| `X-Sample-Rate` | 샘플레이트 (44100) |
| `X-Processing-Time` | 서버 처리 시간(초) |

## 성능 참고

- 처리 시간은 대부분 5단계 음성 합성에서 걸립니다.
- 속도와 품질은 `steps`로 조절합니다. 기본값은 8이고, 낮추면 빨라지고 높이면 품질이 좋아집니다.
- CPU 기준으로 오디오 7.3초 분량을 약 1.8초에 생성했습니다.
- ONNX Runtime은 요청 하나에도 CPU 코어를 모두 사용합니다. 그래서 `TTS_MAX_CONCURRENCY`를 올려도 처리량이 비례해서 늘지 않습니다. 보통은 1–2가 적당합니다.

`POST /v1/audio/speech`(OpenAI 호환)도 요청 형식만 `TTSRequest`로 바꾼 뒤 같은 `synthesize()` 흐름을 따릅니다.
